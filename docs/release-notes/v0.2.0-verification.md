The evidence behind `docs/release-notes/v0.2.0.md`, ticket W23-10, 2026-11-02. Every number below
was produced on that day. The commands are in `docs/RELEASE.md`.

## Bundle smoke: arm64, clean VM

Lima VM `rp-clean-0200`, created for this test: Ubuntu 26.04.1 with distro Podman 5.7.0 and
podman-compose 1.5.0. No host mounts, so no checkout was visible inside it. The tarball was copied
in with `limactl copy`.

1. `sha256sum -c` OK. `tar -xzf` printed **nothing**. (The first build printed 1,713 "Ignoring
   unknown extended header keyword" lines from macOS xattrs; fixed in `deploy/bundle.sh`.)
2. `ADMIN_PASSWORD=… ./install.sh --url=http://localhost:8099 --admin-email=…` exit 0. All
   services ran: postgres, valkey, scan-runner, api, worker, web; migrate exited 0.
3. `/healthz` 200. Sign-in returned `must_change_password: true`. The password change returned 200,
   sign-in with the new password 200. `GET /api/v1/about` → `{"version":"0.2.0"}`.
4. `LICENSE`, `NOTICE` and `THIRD_PARTY_NOTICES.md` are present in the api and web images.
5. `deploy/smoke-report-pdf.sh`: **PASS**, report #1 as a 2-page PDF (133,103 bytes).
6. `compose down` (volumes kept), then `./up.sh` exit 0. The changed password still signs in, and
   report #1 is still `ready`.
7. Walk-through at 1440px light and dark and at 390px, across Overview, Setup, Repositories,
   Models, Rules, Reports, About and Findings: 24 captures, no horizontal overflow, no console
   errors.

## Bundle smoke: amd64, under emulation only

Same VM, with the arm64 stack and its volumes removed and `qemu-user-binfmt` installed.
`install.sh` was run with the `REPOPULSE_ALLOW_EMULATED_ARCH=1` test hatch.

1. `sha256sum -c` OK. `tar` printed nothing. All images loaded as amd64.
2. **Deviation:** `valkey:9.0.7-alpine` for amd64 segfaults under qemu-user (exit 139), as
   `redis:7-alpine` did on 2026-09-23. The native arm64 Valkey was substituted. postgres, migrate,
   api, worker, web and scan-runner all ran amd64.
3. `/healthz` 200. The forced password change worked. `/api/v1/about` → `0.2.0`.
   `/api/v1/setup/status` 200.
4. **Not testable here:** the report PDF. Headless Chromium in the worker traps under qemu-user
   (`uncaught target signal 5`), so the report is marked failed.
5. `compose down` / `up.sh` exit 0. The changed password survives.

Not tested anywhere: a real amd64 CPU, Docker, and a scan end to end from a bundle install.
A real amd64 host (W11-05) is still needed before amd64 can be called tested.
