## Review-quality evals (Claude Haiku via the Claude Code CLI, temperature 0.1)

Prompt and checklist changes since 0.2.0, found by diff against `v0.2.0`:

- a new combined first-look prompt, `combined.v1` (`packages/analysis/src/specialists/combined.ts`);
- the `code_health` and `anti_slop` scanner catalogue versions moved from v1 to v2
  (`packages/security/src/catalogue.ts`): non-production paths are no longer measured. These
  are scanner versions, not model prompts; the specialist checklists are unchanged (below);
- a retry nudge for a reply with reasoning but no answer (`specialists/run.ts`);
- `AI_QUICK_VERDICTS=on` by default, which sends `reasoning_effort: "none"` for the triage,
  judge and CVE verdicts (`t2/client.ts`).

**Model used: Claude Haiku (`claude-haiku-5-5`) through the `claude_cli` transport, not the
local model.** A local `qwen/qwen3.8-27b` run (seed 7, concurrency 1) was started and did not
finish, and it recorded nothing, so 0.3.0 has no local-model numbers. The owner chose Haiku to
finish the evals quickly. The run used the same labelled fixtures and scoring as
`packages/security/src/eval/cli.ts`, from the `worker:0.3.0` image: a one-off container with
the existing CLI sign-in volume mounted, where a small wrapper changed only the host. Only these
AI-written fixtures were sent: 39 calls, each logged with its size and digest. Concurrency 2, 134
s, complete, 0 provider errors, 0 format failures. `docs/MODEL_EVAL.md` was not regenerated; it
still shows the 0.2.0 qwen row.

The Haiku transport does not send that field.

## Bundle smoke: amd64, under emulation only

Same VM, project `rpamd`, `qemu-user-binfmt` 11.0.3 installed. `install.sh` was run with the
`REPOPULSE_ALLOW_EMULATED_ARCH=1` test hatch.

1. `sha256sum -c` OK. `tar` printed nothing. All images loaded as amd64.
2. **Deviation, as in 0.2.0:** `valkey:9.0.7-alpine` for amd64 segfaults under qemu-user (exit

   amd64.
3. `/healthz` 200. The forced password change worked. `/api/v1/about` → `0.3.0`.
   `/api/v1/setup/status` 200.
4. **Not testable here:** the report PDF. Headless Chromium in the worker dies under qemu-user
   (`Target page, context or browser has been closed`), so the report is marked failed.
5. `compose down` / `up.sh` exit 0. The changed password survives.

Not tested anywhere: a real amd64 CPU, Docker, and a scan end to end from a bundle install. A real
amd64 host (W11-05) is still needed before amd64 can be called tested.

## Notes for the release

- The VM had no `podman.socket` enabled, so `install.sh` printed the `CONTAINER_SOCKET` warning
  for scan-runner. That happened under 0.2.0 as well. It does not affect the checks above, but a
  customer who skips that step gets no snapshot scans.
- pnpm prints that the `pnpm` field in `package.json` (`overrides`, `onlyBuiltDependencies`) is
  no longer read. The gate passed regardless; moving those settings is a follow-up.
- Doc links in Setup and About point at `github.com/bpmforge/repopulse/blob/v0.3.0`. They need
  the tag pushed and the repository public before customers can open them.
