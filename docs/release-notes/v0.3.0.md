RepoPulse 0.3.0

This release makes the AI layer usable on real repositories and brings its results to the
pull request page. It ships as a self-hosted install bundle per architecture
(repopulse-0.3.0-linux-arm64.tar.gz, repopulse-0.3.0-linux-amd64.tar.gz), each with a .sha256
file. Install with the bundle's README.md: verify the checksum, extract it, run ./install.sh.

Highlights

- An AI first look after the first scan. With a model configured, a short review reads the
  strongest-signal production files and raises findings by area. It runs as a small fixed
  number of model calls and no longer waits behind the CVE checks.
- AI review on the pull request page. Findings from an AI review of a pull request are listed
  under "New on this PR" with the rule findings. Rows that no second model has confirmed are
  marked "not in CI" and do not fail a build; a flag on the CI command counts them.
- The pull request page shows the changed files and the size of the change, and findings
  close by themselves when a later push fixes them.
- Only pertinent code is reviewed. Tests, fixtures, generated and vendored code are skipped by
  code health, anti-slop and every AI step, and do not count toward scores. The secrets scan
  still covers them.
- Less model time. A repository pass re-reads only files that changed, each area reads only
  its own kind of code at function level, CVE checks never re-ask, and verdicts are short.
- New settings to trade AI depth for speed, three new rules that start in shadow, and
  gitleaks' rules imported as shadow candidates for the secrets scanner.
- A refreshed interface: sortable Findings list, Unified, Split and Patch diff views, grouped
  tabs.
- Eleven screenshot tours in docs/tour, one per job.
- No known dependency advisories: zod moved to version 4.

Upgrading from 0.2.0

Follow "Upgrading" in the bundle's README.md: extract the new bundle beside the old one, take a
backup with deploy/backup.sh in the old directory, then copy deploy/.env and the downloaded
vulnerability data into the new one before installing. Migrations 0068-0070 apply on start. No
configuration change is required.

Which model

docs/INSTALL.md "Which model: fast or private" has measured times from one test install. A
local 27B model keeps everything on your network and reviewed one pull request in 47 minutes;
a small hosted model did it in under 3.

Known limitations

- With the Claude Code CLI backend, Settings shows a false "containers disagree" and Test
  connection cannot pass; reviews themselves run.
- A hosted model needs two separate opt-ins, for the review and for the CVE second opinion.
- The CI command needs the full commit id.
- The accuracy benchmark measures the rule-based checks only. There is no accuracy figure for
  the AI layer yet.
- The amd64 bundle is tested under emulation on an arm64 Mac, not on a real amd64 machine.
