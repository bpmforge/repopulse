RepoPulse 0.2.0

RepoPulse is now open source under the Apache License 2.0, and this is the first tagged
release. It ships as a self-hosted install bundle per architecture
(repopulse-0.2.0-linux-arm64.tar.gz, repopulse-0.2.0-linux-amd64.tar.gz), each with a .sha256
file. A bundle carries every image it runs, so installing downloads nothing from anywhere
else. Install with the bundle's README.md: verify the checksum, extract it, run ./install.sh.

Highlights

- Incremental scanning. A weekly or manual scan skips a scanner when a successful run already
  exists for the same commit, tool versions and advisory data. "Run scans now" fetches one
  tarball for every snapshot scanner. The per-file scanners re-read only changed files and
  carry the other findings forward. The Security tab shows each scanner's scope ("up to date",
  incremental since a commit, full) and offers a Full rescan.
- Incremental PR re-review. A new push reviews only the hunks changed since the last reviewed
  head; findings whose lines survive are carried forward.
- Cheaper model calls. Review prompts are split into a cacheable prefix and a per-chunk body,
  and Settings -> Models shows the cache-hit rate.
- A Repository AI review tab beside Security. Models opens on what is configured; Routing
  and Quality per model are easier to read.
- Licensing. LICENSE, NOTICE and THIRD_PARTY_NOTICES.md are in every image and bundle. The
  scan image carries a written source offer for its GPL/LGPL tools. The bundled cache is now
  Valkey 9.0.7 (BSD-3-Clause) instead of Redis 7.4; existing Redis volumes load unchanged.
- Install fixes from a clean Linux test (Ubuntu 26.04 with Podman 5.7, Ubuntu 24.04 with
  Docker): version floors checked up front, compose calls bounded by a timeout, rootless
  Podman configuration.

Upgrading from 0.1.0-rc1

Follow "Upgrading" in the bundle's README.md: extract the new bundle beside the old one, take a
backup with deploy/backup.sh in the old directory, then copy deploy/.env and the downloaded
vulnerability data into the new one before installing. Migrations 0065-0067 apply on start.
The redis service becomes Valkey and reads the existing volume; see RUNBOOK.md "Redis became
Valkey (2026-11)".

Measured for this release (2026-11-02)

- Tests: 5,935 passed, 22 skipped, 0 failed, with live Postgres 16 and Valkey.
- Browser tests (Playwright against the seeded stack): 164 passed, 17 skipped (opt-in
  screenshot tours, a live-model test and a real-GitHub smoke), 0 failed.
- Accuracy (deterministic checks only, no AI model; docs/benchmarks/report.md, commit 3a35f24,
  opengrep 1.27.1): OWASP Benchmark v1.2 precision 0.826, recall 0.798; Juliet Java v1.3
  sample precision 0.560, recall 0.269; Juice Shop code-fix snippets precision 0.700, recall
  0.636. These match 0.1.0 except Juice Shop precision (1.00 before), which fell because of
  three hits from one performance rule on String.includes. The About page shows these
  figures.
- Review quality with a local model (qwen/qwen3.8-27b, docs/MODEL_EVAL.md): triage agreed
  with all 12 labelled cases. The per-role fixtures are four to eight AI-written cases, not
  reviewed by a person, so they are a regression floor, not an accuracy estimate.

Known limitations

- Lodestone and bpm-rulepacks, the retrieval engine and the rule packs RepoPulse builds on,
  become public separately.
- The amd64 bundle was built and smoke-tested under emulation on an arm64 Mac; see the
  bundle's ARCHITECTURES.md.
