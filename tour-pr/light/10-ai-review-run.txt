AI review pass

AI
Reads the files you name, or the diff of a pull request or a short range of commits, through the models you configured, asks specialist reviewers for findings and gives rule-raised findings on the reviewed lines an evidence-backed second opinion. Everything it produces is a suggestion on a finding. It changes no finding and writes nothing to your repository.

Limits: at most 50 paths, 40 files and 400 KB read (of source, or of diff), 30 model calls per pass, and 10 passes a day for the workspace (passes that ran, failed ones included; a scheduled run that was skipped does not count). Over a limit the pass is refused with the reason; it never reads part of what you asked for and calls it all.

What to review
Files or directories

Files or directories to review (one per line, relative to the repository root)
Reads JavaScript and TypeScript (.js, .jsx, .ts, .tsx, .mjs, .cjs, .vue, .svelte), Python, Go (and go.mod), Ruby, Java, Kotlin, Scala, C#, PHP, Rust, Swift, C and C++, Objective-C, Dart, Elixir, shell scripts, Terraform (.tf, .hcl), YAML and SQL files only, each up to 512 KB. Other files in these paths are not reviewed.

Full review: read every file again. Without it, a repeat pass over the same paths sends the model only what changed since the last clean pass and keeps that pass’s findings for the rest.
Include tests: also review test code under these folders. Without it, test files are left out so the model spends its time on the code that runs. A test file or folder you name yourself is always read.

Where the code goes: Leaves your network: Claude CLI (Haiku) (api.anthropic.com) would receive the contents of the files in scope, or the diff of a pull request, with their paths. Each request is recorded in the egress audit.
